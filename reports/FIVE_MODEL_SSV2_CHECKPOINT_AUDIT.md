# Five-model SSV2 checkpoint availability audit

Audited 2026-09-13 against the fixed K400 and SSV2 1,000-clip benchmark. **Author-released SSV2 classifiers are external baselines; none is a final checkpoint from this project's controlled K400 → SSV2 training protocol.** No `runs/ssv2/<model>/<run-id>/best.pth` or required final-run sidecars exist. The fixed K400 and SSV2 manifests each list 1,000 clips, and all 2,000 listed video paths exist locally. The [dataset audit](SSV2_DATASET_AUDIT.md) still reports 82,233 missing SSV2 *training* videos and 12,010 missing validation videos outside the selected fixed sample, so controlled training is not yet a legitimate complete-data run.

`READY_OFFICIAL_SSV2` below means an exact model-size author release with a 174-class SSV2 classifier and a live binary endpoint. It does **not** mean the file is a controlled final result or that the current adapter has been routed to every author recipe. Negative findings mean no exact checkpoint was found in the sources searched, not proof that none exists anywhere.

This Windows Python lacks `timm`, so actual construction of the UniFormer and VideoMAE adapters stopped at `ModuleNotFoundError: timm`; the full benchmark preflight also stopped during `pandas` import with `ValueError: source code string cannot contain null bytes` in the local Python installation. Full controlled SSV2 fine-tuning must wait for the complete official SSV2 training videos.

## Reproducible local checks

The [25-file inventory](five_model_checkpoint_inventory.csv) records path, byte size, streaming SHA256, state-dict wrapper, tensor count, classifier shape, decoder shape, and inspection errors for **every** local checkpoint filename in the five target families. Recreate it with `python scripts/audit_five_model_checkpoints.py`. It uses `torch.load(weights_only=True, mmap=True)` for PyTorch files and `safetensors.safe_open` for the one local safe tensor file. All 25 files inspected without error. All five frozen K400 source SHA256 values match their local files, and both fixed manifest SHA256 values match `configs/frozen17.yaml`. No candidate is a smoke or partial final run: `runs/ssv2/` does not exist, and the final runner requires a project `best.pth` plus `protocol_status.json`, `complete.json`, and `best_metadata.json` with final status.

Backbone tensor-key and shape comparisons against the exact local K400 counterparts found **no missing or extra tensor keys** for UniFormer-S (331 tensors), UniFormer-B 32-frame (687), UniFormer-B 16-frame (687), or VideoMAE-B (162). For each pair, only `head.weight` and `head.bias` changed shape from 400 to 174 classes. This is strong graph-compatibility evidence, not a strict runtime load test. UniFormer-B 32-frame K400 file `checkpoints/uniformer/uniformer_base_k400_32x4.pth` is 199,525,573 bytes and SHA256 `b432450566cdc4f50222e4851b5d304bba4444a699cdbb43fa529ceb18ae1f8e`, **exactly matching** the [first-party Sense-X HF LFS object](https://huggingface.co/Sense-X/uniformer_video/blob/main/uniformer_base_k400_32x4.pth). The former `BLOCKED_EXACT_ARTIFACT` marker in `configs/frozen17.yaml` was stale and has been corrected to `READY_EXACT`. The [checkpoint manifest](../checkpoints/manifest.csv) now records both this verified source and the unverified local Base 32-frame SSV2 candidate. Its 16×4 neighbor hashes differently and is not the frozen source.

Important rejections from the inventory: `checkpoints/videomae/videomae_ViT-B_ssv2_checkpoint.pth` is a **pretraining** graph (`decoder.head.weight` `[1536,384]`), despite its name, and has no 174-class classifier. The ViT-S/L files are wrong sizes. `checkpoints/legacy_ssv2_released/video-focalnet_base_ssv2.pth` has a 174-class `[174,1024]` head but is Base, while Tiny has `[400,768]`. DualFormer Small/Base files are also wrong variants. K400-only weights must not be added to an SSV2 checkpoint map.

## Public link checks and source limits

Live binary means an anonymous `GET` with `Range: bytes=0-0` returned `206 application/octet-stream` and `Content-Range`, without transferring the checkpoint. On 2026-09-13, UniFormer-S Drive returned `0-0/85271581`, UniFormer-B 16-frame Drive `0-0/199061829`, VideoMAE-B 2400 Drive `0-0/172756423`, and VideoMAE-B 800 Drive `0-0/172756423`. The last file was not downloaded, so its classifier state and hash were not independently inspected; the [author model zoo](https://github.com/MCG-NJU/VideoMAE/blob/main/MODEL_ZOO.md) identifies it as the fine-tuned model rather than its separate pretraining link. UniFormer-B 32-frame preK400 Drive returned **404** for both viewer and binary endpoint. The [Sense-X HF 32-frame preK600 binary](https://huggingface.co/Sense-X/uniformer_video/resolve/main/uniformer_base_sthv2_32_prek600.pth) returned `206 application/octet-stream`, `0-0/199061829`; its [first-party LFS commit](https://huggingface.co/Sense-X/uniformer_video/commit/97b6ead94300fe18ffee87a864d3787fbc3f4438) publishes the SHA256 shown above. A Drive viewer response of 200 alone was **not** counted as a binary check.

The [UniFormer author table](https://github.com/Sense-X/UniFormer/blob/main/video_classification/README.md) separates Small/Base, K400/K600 pretraining, and 16/32-frame SSV2 rows. The [VideoMAE author table](https://github.com/MCG-NJU/VideoMAE/blob/main/MODEL_ZOO.md) separates 800/2400 pretraining epochs and pretrain versus fine-tune links. The [VideoMAE HF converted classifier](https://huggingface.co/MCG-NJU/videomae-base-finetuned-ssv2) is an additional public option under a `cc-by-nc-4.0` model-card license, but its Transformers state format is not the project's strict original-PyTorch adapter format; its model card says 70.6% and elsewhere incorrectly mentions 400 K400 labels, so it is not used to substantiate the 70.8% author-table value. The author's original Drive file is the adapter-ready source. Check checkpoint-specific redistribution rights before sharing local weight files with a teammate; links and hashes can be shared.

The [Video-FocalNets author repository](https://github.com/TalalWasim/Video-FocalNets) and [paper](https://openaccess.thecvf.com/content/ICCV2023/papers/Wasim_Video-FocalNets_Spatio-Temporal_Focal_Modulation_for_Video_Action_Recognition_ICCV_2023_paper.pdf) publish Tiny for K400 but only Base on SSV2. The [third-party Keras port](https://github.com/innat/Video-FocalNets/blob/main/MODEL_ZOO.md) also offers only Base SSV2 and would not directly match the PyTorch adapter. The [DualFormer author repository](https://github.com/sail-sg/dualformer) lists Tiny K400, with no SSV2 checkpoint; a [later training study](https://www.ecva.net/papers/eccv_2024/papers_ECCV/papers/01635.pdf) likewise reports its Tiny DualFormer/Video-FocalNet experiments on K400, not SSV2. Indexed searches for likely `ssv2`/`sthv2` filenames, Drive IDs, forks, Hugging Face, Kaggle, ModelScope, OpenMMLab/MMAction2, and archives yielded no exact Tiny SSV2 artifact. Those are bounded search results; a private or unindexed run could still exist.

## Checkpoint-map decision

The **controlled final** `scripts/benchmark_finetuned_ssv2.py --checkpoint-map` requires exactly five entries pointing to completed `runs/ssv2/<key>/<run-id>/best.pth` plus matching sidecars. **Zero entries can be filled today**:

```json
{}
```

That empty object documents availability; it is **not** an executable five-model map. The runner correctly rejects it. The external-baseline paths that can be benchmarked separately today are `checkpoints/legacy_ssv2_released/uniformer_small_sthv2_16_prek400.pth`, `checkpoints/legacy_ssv2_released/uniformer_base_sthv2_16_prek400.pth` (16-frame recipe only), and `checkpoints/legacy_ssv2_released/videomae_vit_b_ssv2_2400e.pth`. Do not put those in the controlled map. For a 32-frame Base external baseline, download the first-party **preK600** HF file to a new path, verify its published LFS SHA256, and explicitly route the 32-frame SSV2 config; the local preK400 SSV2 file needs independent source authentication. The exact controlled K400→SSV2 plan is unchanged except that **all five exact K400 source checkpoints are now available**; the stale UniFormer-B source blocker is removed. Complete the SSV2 training pool, train and select five final runs, then populate the five required `best.pth` map entries.

The benchmark progress bar introduced in commit `283262d` updates only when control resumes after a fully processed chunk. In `run_benchmark.benchmark`, `power_logger.stop()` runs in the chunk's `finally` before the iterator resumes and calls `bar.update`, and each `time.perf_counter()` interval surrounds only model inference. Progress display is therefore outside both measured inference timing and active power sampling. The frozen K400 result-row `ModelFrames`/`FramesUsed` now preserves the frozen 32-frame UniFormer-B recipe instead of being overwritten by the older 16-frame registry metadata.
